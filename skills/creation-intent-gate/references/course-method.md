## 第九课：意图建模

核心判断：当 AI 让执行越来越便宜，最大的杠杆不是更快规划或构建，而是先提高意图质量。

### Mission

Mission 描述一次有价值的状态转化：帮助谁，把什么转化成什么。产品、功能、渠道、数字目标和当前欲望通常只是实现齿轮。

### Vision

Vision 是转化成功后的多种运行画面。AI 负责大量展开和显化，让人站在未来样本之外判断：它是否有价值，是否愿意生活在这种状态里，以及它带来什么代价。

### Values

Values 是在多种可能成功的画面中做选择。它不是墙上的口号，而是判断哪些画面自洽、他洽、值得进入现实，哪些虽然有效但不属于自己。

### 人机分工

- 人：定义 Mission，完成 Values 判断。
- AI：展开和显化 Vision，搜集证据，帮助压缩差异。

## 第十课：碰撞现实

核心判断：AI 时代 build 的价值不只是速度，而是低成本、高频率地制造预测偏差，加速形成新的 sense。

### 用户价值

课程公式：

> 战略 = 用户价值
>
> 用户价值 = 新旧体验差 - 替换成本

评价创造物时，必须把它与目标对象现有解决方式比较，而不是孤立评价功能。

### 最大卡点

现实碰撞不是每天做很多容易的小事。先找限制系统的最大卡点，再把针对它的最小创造物推入现实。

### 碰撞记录

每轮至少保留：原预测、现实对象、实际反馈、预测偏差、新收获、下一步。

## 第十一课：端到端回路

核心判断：把 All-in-Context、AI、脚本、数据、证据和反馈组成可运行、可验证、可升级的端到端系统。

### 两个原则

1. 可以人在回路上的，就不要人在回路中。人负责意图、授权、批准、审计和治理，不负责中段搬运。
2. 可以使用古典机器的，就不要使用神经系统。确定、重复、可验证的步骤优先用脚本、规则、数据库和接口；大模型处理语义、模糊判断和复杂 Context。

### 八层回路

1. 单 Agent 目标导向运行：单个 Agent 围绕目标完成一次任务。
2. 多 Agent 目标导向运行：多个 Agent 协作完成一次任务，能力更强但路径不稳定。
3. 固定工作流，人在回路中：流程固定，但人仍在中段不断衔接。
4. 固定工作流，人在回路上：人在开端定义、末端批准，中段由 AI、脚本和数据运行。
5. Backtesting Loop：用历史数据在上线前回测和校准；前提是交付可验证。
6. Realtime Adaptive Loop：在真实运行中发现偏离并提出修复。
7. Meta Adaptive Loop：不只调参数，开始提出规则本身的新增、修改和淘汰。
8. Evolutionary Loop：多套候选系统产生变体、竞争、组合和淘汰。

不要跳级叙事。判断当前真实层级，只设计到下一层的可验证升级。

## 归因边界

- Mission、Vision、Values 的意图建模来自第九课。
- “Values 要判断自洽和他洽”来自课程；1-5 分评分、二维象限和决策颜色是社区案例与本 skill 的工程化表达，不是课程原始固定模板。
- 用户价值公式、最大卡点、最小创造物和预测偏差来自第十课。
- 双速门、强制 Build Gate、文件命名和视觉交付规则是本 skill 为稳定执行增加的契约，不要冒充老师原话。
- 象限坐标、市场定位和置信度是分析判断，必须附证据与不确定性，不能称为厂商官方评分。

## 课程来源发现

本参考已经包含运行 skill 所需的最低方法，不依赖外部课程文件才能工作。需要核对课程原意时：

1. 优先使用用户本轮提供的课程目录或文件。
2. 未提供路径时，从当前工作区和已知 Vault 根目录搜索以下相对模式：
   - `09_第九章_意图建模/*课程整理.md`
   - `10_第十章_碰撞现实_战略/*课程整理.md`
   - `11_第十一章_回路n/*课程整理.md`
3. 找到多个 Vault 时，优先当前工作区所属 Vault；仍有歧义时再询问用户。
4. 找不到原始课程文件时，使用本参考继续，并明确标记“本轮未核对课程原文”，不要报错或中断创造流程。

课程文件可用时优先核对原文；本参考用于快速执行，不替代原始材料。
