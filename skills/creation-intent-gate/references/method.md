## 意图建模

当 AI 让执行越来越便宜，最大的杠杆通常不再是更快规划或构建，而是先提高意图质量。

### Mission

Mission 描述一次有价值的状态转化：帮助谁，把什么可观察的当前状态转化成什么目标状态，同时不牺牲哪些关键边界。

产品、功能、渠道、数字目标和当前欲望通常只是实现方式，不应直接冒充 Mission。一个合格的 Mission 在去掉当前工具名称后仍然成立。

### Vision

Vision 是转化成功后的不同运行画面。它描述创造物真正运行起来后，目标对象如何生活或工作、人和 Agent 如何分工、价值如何产生、事实和反馈如何沉淀，以及必须承担什么代价。

AI 负责展开和显化多种未来样本；人站在这些样本之外判断，自己是否愿意长期生活在这种状态里，以及它是否值得进入现实。

### Values

Values 是面对多个可能成功的 Vision 时使用的选择规则和禁区。它回答：什么必须保留，什么代价不能接受，哪些事情即使有效也不做。

“真实、透明、简单、用户优先”等通用好词不能直接作为 Values。有效的 Values 必须能在两个有吸引力但互相冲突的选项之间产生明确取舍。

### 人机分工

- 人：确认 Mission，判断 Values，选择代价，承担对外承诺和最终责任。
- AI：读取 Context，展开 Vision，搜集证据，生成样本，压缩差异，设计验证动作。

## 现实碰撞

意图收敛后，不继续停留在战略文档中，而是用一个最小创造物进入真实流程，低成本制造预测偏差。

### 用户价值

使用这个关系判断创造物是否值得被采用：

> 用户价值 = 新体验与旧体验之差 - 替换成本

必须把新创造物与目标对象当前的解决方式比较。替换成本包括学习、迁移、信任、数据、组织协同和心理负担。

### 最大卡点

不要优先选择最容易完成的任务。先找到当前真正限制系统前进的最大卡点，再针对它设计 1–3 天内可完成的最小创造物。

### 碰撞记录

每轮至少保留：

- 原预测：在接触现实前认为会发生什么。
- 现实对象：交给哪个真实的人、客户或流程使用。
- 实际反馈：对方真实做了什么，而不只是说了什么。
- 预测偏差：现实与原预测哪里不同。
- 新判断：这次偏差改变了什么认识。
- 下一步：保留、修改或停止什么。

## 端到端回路

把 Context、AI、脚本、数据、证据、人的质量门和反馈组成可运行、可验证、可升级的系统。

### 两个原则

1. 尽量让人在回路上，而不是人在回路中。人负责意图、授权、批准、审计和治理，不负责中段搬运。
2. 确定、重复、可验证的步骤优先使用脚本、规则、数据库和接口；大模型处理语义、模糊判断和复杂 Context。

### 八层回路

1. 单 Agent 目标导向运行：单个 Agent 围绕目标完成一次任务。
2. 多 Agent 目标导向运行：多个 Agent 协作完成一次任务，能力更强但路径不稳定。
3. 固定工作流，人在回路中：流程固定，但人仍在中段不断衔接。
4. 固定工作流，人在回路上：人在开端定义、末端批准，中段由 AI、脚本和数据运行。
5. Backtesting Loop：用历史数据在上线前回测和校准；前提是交付可验证。
6. Realtime Adaptive Loop：在真实运行中发现偏离并提出修复。
7. Meta Adaptive Loop：不只调参数，开始提出规则本身的新增、修改和淘汰。
8. Evolutionary Loop：多套候选系统产生变体、竞争、组合和淘汰。

不要跳级描述系统。先判断当前真实层级，只设计到下一层的可验证升级。

## 证据边界

- Mission 必须由用户确认，不能由 AI 根据少量信息替用户定案。
- 自洽评分只能基于用户 Context 提议；没有证据时标记为待校准。
- 他洽优先使用真实行为、访谈、付款、配合、旧流程和一手市场资料。
- 评分、象限、市场位置和置信度都是分析工具，不是客观事实。
- 公开发布、付款、合同、隐私、客户承诺和权限变更必须保留人的最终质量门。
- 每轮现实碰撞保留原预测和实际反馈，不用事后解释覆盖旧判断。
